СТРУКТУРА ПОДСТАНОВОК И ПЛЮРАЛИЗАЦИИ — версия 1

Это контракт для будущего подключения. Работающая игра и существующие
переводы ru.po/en.po в этой задаче не меняются.

1. ИДЕНТИЧНОСТЬ
Сообщение имеет постоянный смысловой id, source_revision, context,
parameters и selector. Переводы индексируются языком, затем категорией.
Ключ обмена: (id, locale, selector, category). Номер строки Excel не ключ.
Добавление категории или языка не перезаписывает существующий перевод.
Изменение исходника повышает source_revision и помечает старые переводы
needs_review. Пустая ячейка при импорте означает «оставить как есть».
Удаление перевода требует отдельной операции; устаревшие записи архивируются.

2. КАТЕГОРИИ
Используем CLDR cardinal: zero, one, two, few, many, other. Это метки правил,
а не буквальные числа: русское one включает 21; французское one включает 0.
other обязателен. У языка может быть лишь other. Полный набор и примеры —
в таблице. Для количества монет, машин, слотов и грузов принимаем целые >=0.
Номера уровней не требуют ordinal: «Уровень 15 / Level 15» — обычная строка.
Ordinal (1st, 2nd…) и диапазоны (1–2 дня) имеют отдельные правила, не cardinal.
Не выбирать категории по языковым семьям и не копировать русскую формулу.

3. ПОДСТАНОВКА
Пример вызова будущего API: message('shop.unlock_slot.price', {coins: 21}).
Порядок: проверить параметры → разрешить locale → выбрать полное сообщение
доступного языка → проверить точное числовое исключение (если задано) →
выбрать CLDR-категорию → выбрать форму → форматировать параметры → вставить.
Выбор формы использует исходное число, а не уже отформатированную строку.
Округление для отображения должно быть согласовано с выбором категории.
Форматирование числа использует тот же язык. Подстановка однопроходная:
значения параметров не интерпретируются как повторные шаблоны или разметка.
Отсутствующий или неверно типизированный параметр — ошибка проверки сборки.
В production безопасный fallback не должен показывать сырые {параметры}.

4. ЧИСЛА И ДРОБИ
Для будущих дробных величин хранить точное десятичное значение строкой
с масштабом: '1', '1.0', '1.00', '1.5'. Не терять видимые знаки после запятой
через float: CLDR может различать 1 и 1.0 (например, ru и en).
Основные операнды: n — абсолютное число; i — целая часть; v — число видимых
дробных знаков с нулями; w — без нулей; f/t — дробная часть с/без нулей.
Компактные миллионы/тысячи используют дополнительные операнды c/e.
Первый этап поддерживает только полные неотрицательные целые. Дроби,
компактные числа и ordinal нельзя незаметно прогонять через integer API.
Все шесть категорий сохраняются в формате для последующего расширения.

5. ЦЕЛЫЕ ФРАЗЫ И ПАРАМЕТРЫ
У каждой формы свой полный текст. Например: «Не хватает {coins} монеты»,
«Не хватает {coins} монет». Не приклеивать отдельно переведённое «монета»:
падеж зависит от фразы. Порядок именованных параметров можно менять.
Параметр селектора может не выводиться: арабская форма для одного/двух
предметов может обходиться без цифры. Такой пропуск должен быть явно
разрешён в метаданных конкретной формы, а не считаться потерей переменной.
Все остальные обязательные параметры должны присутствовать во всех формах.
Точный случай '=0' можно задать для «Нет монет», но это UX-исключение,
не новая CLDR-категория. Приоритет: exact → category → other.
Несколько независимых количеств требуют вложенных селекторов или отдельных
полных сообщений. Нельзя выбирать форму всего предложения по первому числу.
Пол/род персонажа — отдельный select, не plural.

6. FALLBACK И ПОЛНОТА
Язык с регионом ищется по явной цепочке, например en-GB → en → ru.
Региональные правила pt-BR и pt-PT различаются: не отбрасывать регион
до выбора категории. JP/KR/CH — названия вкладок, не коды языков:
для данных нужны ja, ko, zh-Hans/zh-Hant; вариант китайского уточняется.
В переводе должны быть все категории, достижимые для типа параметра,
и other. Незавершённый перевод не публиковать: fallback всего сообщения
на исходный язык с его правилами, а не отдельного слова/формы.
Арабский дополнительно требует RTL, поддержки шрифта и изоляции вставок
с другим направлением. Плюрализация сама по себе этого не обеспечивает.

7. PO И EXCEL
Таблица переводов: ID, locale, selector, category, source_revision,
исходная фраза, перевод, статус, контекст. Одна форма = одна строка.
Допустимы только категории выбранного языка. Порядок строк не важен.
CLDR-категория не равна индексу msgstr[n]. Для стандартного gettext
нужны согласованные Plural-Forms и отдельная таблица индексов каждого языка.
Для сохранения расширяемой структуры предлагаем экспортировать формы как
отдельные PO-записи с msgctxt '<id>|cardinal|<category>'. Runtime выбирает
категорию через CLDR, затем получает соответствующий перевод из PO.
Это не автоматическая работа Godot tr_n: понадобится адаптер локализации.
Нельзя одновременно применять оба механизма выбора формы к одной строке.
Текущие PO сохраняем до отдельной миграции с таблицей старых/новых ID.

8. ПРОВЕРКИ
Проверять границы 0,1,2,3,4,5,10,11,12,14,20,21,22,25,99,100,101,102,
103,111,112,114,1000,1000000; отдельно 1.0/1.5 для будущих дробей.
Проверять отсутствие неизвестных параметров, полноту форм, fallback целиком,
сохранение переводов при добавлении строки и повторном импорте пакета.
В приложенной таблице примеры категорий рассчитаны Intl.PluralRules
из установленного Node (CLDR 48). В игре правила нужно зафиксировать той же
версией или обновлять все языки вместе с повторным прогоном тестов.
