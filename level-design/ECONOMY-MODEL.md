# Экономика монет: точная модель и оптимизация

Задача модели — найти параметры экономики и сложности уровней, при которых
игра зарабатывает больше всего при заданной ценности вовлечения. Готовых
целевых цифр нет: внешние документы — только примеры. Цели задаются весом
вовлечения $\lambda$ и ограничениями в `level-design/economy/economy_search.json`.

```text
конвейер уровней (Godot)                               модель экономики (Python)
generate → evaluate → sequence ─levels.json─▶ точная модель ─▶ LTV, вовлечение, удержание
           (сложность, интерес, польза бустеров)     │
                       сдвиг сложности, параметры ◀──┴── оптимизатор (граница компромиссов)
```

```text
python level-design/economy/run_economy.py --levels bus-bloom/generated_levels/levels.json
python level-design/economy/run_economy.py --levels ... --validate      # точная модель против симуляции
python level-design/economy/run_economy.py --levels ... --sensitivity   # курсы обмена рычагов
python level-design/economy/run_economy.py --levels ... --optimize      # граница компромиссов (~70 мин)
```

Все цифры ниже посчитаны на 100 уровнях, собранных конвейером
(`tools/build_levels.gd`, пул 1200 кандидатов).

## 1. Польза бустеров — измерено по каждому уровню

`LevelSolver.booster_profile` проигрывает модель игрока (навык 0,7) на
настоящих правилах игры:

- с 3, 4 и 5 слотами со старта — Extra Slot до начала уровня;
- в каждом тупике — +1 слот или перемешивание настоящей
  `LevelBoosters.shuffle_remaining`: по 10 случайных перестановок на тупик.
  В установившемся тупике рабочий ничего не несёт, поэтому на месте
  остаётся только уже погруженный груз.

| Тип уровня | Тупик с 3 / 4 / 5 слотами | Снова тупик после 1-го / 2-го слота | Снова тупик после перемешивания | Безнадёжные тупики* | Разброс** |
| --- | --- | --- | --- | ---: | ---: |
| лёгкий | 9,3 / 1,4 / 0,2 % | 16 / 7 % | 90 % | 64 % | 0,15 |
| средний | 24 / 4,7 / 0,9 % | 19 / 16 % | 92 % | 60 % | 0,15 |
| сложный | 42 / 8,0 / 1,1 % | 17 / 10 % | 92 % | 67 % | 0,13 |
| мягкий гейт | 68 / 27 / 8,6 % | 39 / 27 % | 94 % | 64 % | 0,14 |
| гейт на +1 слот | 100 / 23 / 5,0 % | 24 / 15 % | 93 % | 70 % | 0,12 |

\* ни одна из 10 перестановок не помогла;
\** стандартное отклонение исхода перемешивания внутри одного тупика
(0 — предсказуемо, 0,5 — монетка).

Выводы:

- **Слот выводит из тупика в 61–85 % случаев, перемешивание — в 6–10 %.**
  Ни на одном из 90 обычных уровней перемешивание не лучше слота. Причина:
  в тупике все слоты заняты машинами «не того» цвета, и случайная очередь
  редко приносит подряд нужный им груз.
- **Случайность почти не важна:** исход определяется положением на поле.
  Две трети тупиков безнадёжны при любой перестановке.
- **5-й слот** снижает повторный тупик ещё в 1,2–2 раза, в зависимости от уровня.
- **Extra Slot до начала** уменьшает тупики в 5–7 раз и превращает гейт на +1 слот
  в обычный уровень (23 % тупиков вместо 100 %).

## 1а. Умное перемешивание и обучение

**Умное перемешивание** (`LevelBoosters.smart_shuffle`) берёт $K$ случайных
перестановок оставшейся очереди и оставляет ту, которую стоящие в слотах
машины используют лучше всего (`shuffle_score`: заполненная машина освобождает
слот и весит 1000, каждая погруженная единица — 1). $K = 1$ — обычное
перемешивание. Кандидаты случайны, поэтому даже сильное перемешивание
помогает не каждый раз: это и есть элемент сложности.

| Тип | Помогает при K = 1 / 2 / 4 / 8 / 16 | +1 слот | Безнадёжные при K = 8 | Разброс при K = 8 |
| --- | --- | ---: | ---: | ---: |
| лёгкий | 11 / 15 / 21 / 27 / 29 % | 84 % | 51 % | 0,16 |
| средний | 10 / 16 / 22 / 27 / 32 % | 82 % | 44 % | 0,18 |
| сложный | 8 / 13 / 18 / 23 / 26 % | 84 % | 52 % | 0,17 |
| мягкий гейт | 7 / 9 / 13 / 16 / 18 % | 65 % | 52 % | 0,18 |
| гейт на +1 слот | 6 / 11 / 16 / 22 / 25 % | 77 % | 56 % | 0,15 |

**Обучение перемешиванию** — уровни 6, 8 и 12. Отбор (`LevelSolver.tutorial_profile`):

- на 3 слотах решатель **доказывает**, что уровень не проходится ни при каком порядке;
- игроки четырёх уровней навыка доходят до тупика (40 прогонов). В **каждом**
  тупике находится умное перемешивание (K = 8, до 60 попыток), после которого
  решатель находит победу;
- 8–10 машин и 3 цвета, после подсказки выигрывают ≥ 60 % игроков.

Отдельный пул из 400 маленьких уровней дал 13 кандидатов, основной пул — 1;
расстановщик взял 3:

всегда 5) ещё нужно сделать в игре.
## 2. Состояние игрока и переходы

Каждый сегмент игроков $g$ (казуальный 55 %, основной 40 %, платящий 5 %)
описывается **распределением вероятностей** $P_L(p, S, b)$ в начале уровня $L$:

- $p$ — сколько пакетов монет уже куплено (0…3+, только у платящих);
- $S$ — длина серии **чистых** побед: без проигрыша и без спасения;
- $b$ — баланс монет (шаг 10, верхняя граница 3000).

Попытка $k$ уровня $L$ при навыке $s_g(L) = s_0 + (s_1 - s_0)(1 - e^{-L/\tau})$:

1. Приток за время: $b \mathrel{+}= \ell\, t_L$, где $\ell$ — ежедневный вход,
   распределённый по игровому времени, а $t_L = 25 + 5\,n_{машин}$ с.
2. **Extra Slot до начала** (сложные уровни или после провала): при $b \ge 2c_{boost}$
   покупается с вероятностью $\beta_g$. Тупик: $p = p_{fail}(L, s) \cdot f_4/f_3$.
3. Тупик с вероятностью $p$. **Дерево помощи**, не больше 2 инструментов за попытку;
   $e$ — сколько слотов уже добавлено:
   - игрок платит, если может, с вероятностью $w = w_g + 0{,}4(N_L - 0{,}5) + 0{,}15\min(S,5)/5$.
     Если по карману оба инструмента, он выбирает перемешивание с вероятностью $\chi_g$
     (цена $c_{sh}$), иначе слот (цена $c_j$ растёт с каждым слотом в попытке);
   - иначе слот за рекламу $r_g$;
   - иначе при нехватке монет пакет с вероятностью $\pi_g\,\delta^{p}$ ($\delta = 0{,}5$ — насыщение);
   - иначе бесплатный слот на гейте при $k \ge 3$;
   - иначе отказ.

   После инструмента тупик повторяется с **измеренной** вероятностью
   $q^{slot}_{e}$ или $q^{shuffle}_{e}$ (раздел 1). Слотов не больше 5.
4. Победа: за чистую $R = R_{base}(L) + B_{clean}(S{+}1)$, со спасением $R_{base}(L)$
   (серия замораживается). Удвоение за рекламу с вероятностью $d_g$. Сундук каждые 10 уровней
   и достижения за число уровней. Скин, если $b \ge c_{skin} + 100$.
5. Уход после победы: $h_g^{win}(1 + 1{,}2(1 - I_L)) + h^{int}_L$; после отказа
   $h_g^{fail}(1 + 0{,}6\,k)$, ×2, если не хватает даже на самый дешёвый инструмент.

$R_{base}(L) = \min(100,\ a + \lfloor b_r\sqrt{L} \rfloor)$, $B_{clean}(S) = \sigma\,\min(S_{cap}, S)$.

**Межстраничная реклама** показывается только после победы: с уровня $L_0 \ge 5$, когда с прошлого
показа прошло $N \in [3, 8]$ выигранных уровней и не меньше $T_{min} = 60$ с игры. Если между
показами $\Delta$ секунд, в сессию длиной $T$ попадает $T/\Delta$ показов, и
каждый стоит

$$h^{int} = h_0\,\bigl(1 + \varphi\,\max(0,\ T/\Delta - 1)\bigr),\qquad h_0 = 0{,}4\ \text{п.п.},\ \varphi = 0{,}25.$$

Это усталость: чем чаще реклама, тем дороже каждый показ.

**Доход с установки:**

$$LTV = \frac{e_{rv}}{1000}E[\#RV] + \frac{e_{int}}{1000}E[\#INT] + (1 - fee)\,E[\$IAP],$$

где $e_{rv} = 10$ \$, $e_{int} = 5$ \$, комиссия 30 %. **Вовлечение** $E[N]$ — ожидаемое
число пройденных уровней из 100.

Модель **точная**: распределение переносится по уровням без выборки, расчёт
детерминирован и занимает 1–3 с. Агентная симуляция на тех же правилах
(`economy_model.py`) с ней сходится:

| | точная модель | 20 000 игроков |
| --- | ---: | ---: |
| прошли 10 / 30 / 100 уровней | 80,5 / 51,2 / 12,8 % | 80,7 / 52,1 / 13,1 % |
| пройдено уровней | 41,05 | 41,30 |
| рекламы с вознаграждением / межстраничной | 16,62 / 11,53 | 16,81 / 11,61 |
| куплено слотов / перемешиваний / Extra Slot | 7,37 / 9,20 / 1,28 | 7,41 / 9,22 / 1,29 |
| покупки, \$ | 0,054 | 0,052 |

Остаточное расхождение до 1 п.п. даёт шаг баланса в 10 монет около пороговых цен.

## 3. Условие оптимума

Максимизируем $J = LTV + \lambda\,E[N]$ при ограничениях: до 10 уровня доходят
≥ 70 % игроков, тупиков без денег даже на самый дешёвый инструмент («стен»)
≤ 25 %. $\lambda$ — сколько долларов стоит один дополнительный пройденный уровень.

**Курс обмена** рычага $x$:

$$k_x = -\frac{\partial LTV / \partial x}{\partial E[N] / \partial x}\quad[\$ \text{ за уровень}].$$

В оптимуме курсы незажатых рычагов равны $\lambda$.

Курсы в стартовой точке ($LTV = 0{,}261$ \$, $E[N] = 41{,}1$), шаг в сторону вовлечения:

| Рычаг | ΔLTV | ΔE[N] | $k_x$, \$/уровень |
| --- | ---: | ---: | ---: |
| Extra Slot до начала −25 монет | −0,04 % | +0,03 | 0,003 |
| уровни легче (−0,2 логита) | −3,2 % | +2,21 | **0,004** |
| старт +50 монет | −0,9 % | +0,35 | 0,007 |
| эскалация 2-го слота −0,5 | −0,2 % | +0,06 | 0,010 |
| награда $a$ +2 | −0,8 % | +0,19 | 0,011 |
| ежедневный вход ×1,25 | −0,6 % | +0,12 | 0,013 |
| перемешивание −10 монет | −1,7 % | +0,33 | 0,013 |
| межстраничная реже (каждые 4) | −3,3 % | +0,60 | 0,015 |
| шаг серии +1 | −0,9 % | +0,16 | 0,015 |
| слот −10 монет | −1,9 % | +0,28 | 0,018 |
| рост награды $b_r$ +0,5 | −1,1 % | +0,16 | 0,019 |
| потолок серии +1 | −0,5 % | +0,04 | 0,033 |

Рамки межстраничной рекламы: первый показ не раньше 5-го уровня, не чаще раза в

### Где предлагать перемешивание

В модели игрок, которому по карману и слот, и перемешивание, выбирает
перемешивание с вероятностью $\chi_g$ = 0,4–0,6. Если вместо этого показывать
перемешивание **только когда на слот не хватает монет** (дешёвый запасной шанс):

| профиль | K | наравне со слотом: LTV / E[N] / до 100 | только при нехватке на слот |
| --- | ---: | --- | --- |
| старт | 1 | 0,261 / 42,0 / 13,2 % | 0,266 / 47,5 / 18,5 % |
| старт | 16 | 0,259 / 44,6 / 15,1 % | 0,264 / 48,1 / 18,8 % |
| λ = 0,01 | 16 | 0,300 / 46,1 / 15,2 % | 0,304 / 47,5 / 16,8 % |
| λ = 0,02 | 16 | 0,256 / 49,3 / 19,3 % | 0,256 / 51,4 / 21,8 % |

Умное перемешивание сократило вред от выбора «не того» инструмента в 1,6–2,4 раза,
но не убрало его: перемешивание помогает в 3 раза реже слота. **Правило
интерфейса: слот — основное предложение тупика, перемешивание — дешёвый шанс,
когда на слот не хватает монет.** Доход тот же, вовлечение на 1,4–3,5 уровня выше.
### Три инструмента тупика: слот, перемешивание, замена машины

С текущей версии перемешивание дешёвое (10–50 монет) и по умолчанию
предлагается только когда на слот не хватает монет (`rescue.shuffle_menu =
"fallback"`). Добавлена **замена машины** (`LevelSolver.swap_truck`): самая пустая
машина из слота возвращается на парковку, её груз уходит в конец очереди, а самая
вместительная машина цвета головы очереди приезжает даже заблокированной. Цена —
150–500 монет. Игрок выбирает среди доступных инструментов с весами
сегмента (`tool_weights`).

Польза в тупике на 3 слотах (100 уровней кампании):

| --- | ---: | ---: | ---: | ---: | ---: |
| лёгкий | 86–88 % | 76 % | 91 % | 54 % | 29 % |
| средний | 82–83 % | 64 % | 88 % | 60 % | 32 % |
| сложный | 83 % | 55 % | 83 % | 56 % | 24 % |
| мягкий гейт | 65–67 % | 40 % | 74 % | 42 % | 18 % |
| гейт на +1 слот | 74–75 % | 14 % | 78 % | 35 % | 24 % |

\* варианты замены, проверенные отдельно: «срочная доставка» — временный слот, в
который сразу приезжает машина нужного цвета; «отмена заказа» — машина уезжает
насовсем вместе с недостающим ей грузом.

**Замена слабее слота:** тупик вызван нехваткой мест, а замена мест не
добавляет. Если бонус должен быть дорогим и сильным, им может быть **срочная

### Четвёртый инструмент: кран

**Кран** (`LevelSolver.crane_truck`): в тупике открывается временный слот (до конца
раунда, в пределах 5), и стрела крана переносит в него самую вместительную машину
цвета головы очереди прямо с затора. Новых машин и груза не появляется: кран берёт
одну из машин уровня вне очереди. Кран сильнее слота на 64 уровнях из 97:

| средний | 82 % | 89 % | 67 % | 33 % |
| сложный | 84 % | 83 % | 57 % | 27 % |

## 5. Межстраничная реклама: обоснование и риск

Показ приносит $e_{int}/1000 = 0{,}005$ \$. Он окупается, пока дополнительный уход
за показ, умноженный на будущий доход игрока, меньше этой суммы. Без учёта
усталости решение переключается скачком. При $\lambda = 0{,}02$ реклама «каждые 2
уровня» выгодна при уходе до 0,4 п.п. за показ, а уже при 0,8 п.п. — «каждые 10».
С усталостью и ограничением в 60 с переход плавный. Но **оба коэффициента
($h_0$, $\varphi$) не измерены**, и от них зависит этот рычаг больше всех остальных.
Частоту нужно подтвердить A/B-тестом: например, 3 / 5 / 7 уровней, а метрики
этих групп подставить в `behaviour`.

## 6. Ограничения и что откалибровать

- Поведенческие коэффициенты — стартовые оценки: доли сегментов, $w_g$, $r_g$, $d_g$,
  $\pi_g$, $\chi_g$, уход $h$, $h_0$, $\varphi$, eCPM. Надёжнее структура выводов, а не абсолютные
  цифры. После софт-лонча коэффициенты подставляются из аналитики.
- Польза бустеров измерена моделью игрока с навыком 0,7 и масштабируется на
  другие навыки через отношения. Живой игрок может видеть, например, что
  перемешивание бесполезно, и перестать его брать.
- Несколько оптимумов упираются в края диапазонов ($a = 30$, старт 300, сложность −0,6).
- Кампания — 100 уровней. Доход после неё отражает только $\lambda$.
- Достижения за серии и «На волоске» есть только в агентной симуляции.
