# Конвейер уровней: генерация → оценка → расстановка

Все три этапа работают на правилах игры из `bus-bloom/scripts/game_model.gd`:
очередь FIFO, автоматическая погрузка в самую загруженную подходящую машину,
блокировка выезда по прямой. Слоты парковки — это буфер из экономики;
базовое число — 3, бустер Extra Slot добавляет до 5.

```text
godot --headless --path bus-bloom --script res://tools/build_levels.gd
godot --headless --path bus-bloom --script res://tools/build_levels.gd -- --pool=800 --levels=200
godot --headless --path bus-bloom --script res://tests/level_pipeline_test.gd
```

Настройки — `bus-bloom/config/level_pipeline.json`. Результат —
`bus-bloom/generated_levels/levels.json` (уровни с решением) и `report.json`
(расстановка, сводка, разбор пула).

## 1. Генерация — `level_candidate_generator.gd`

Случайная расстановка машин без пересечений, затем порядок выезда без
циклических блокировок. Очередь груза строится по этому порядку с **окном**
`queue_window`: одновременно перемешивается груз не более чем `queue_window`
машин подряд, серии одного груза — до `max_run` штук.

- окно 1 — груз каждой машины идёт сплошным блоком, уровень проходится с 1 слотом;
- окно 3 — нужно до 3 слотов;
- окно 4 — часть уровней требует 4-й слот; такие уровни не попадают в кампанию.

**Машины одного цвета в окне** (`same_color_chance`, диапазон в `pool`). Груз
уходит в самую загруженную машину этого цвета, поэтому порядок отправки
становится решением: например, пикап или большой грузовик первым. Гарантия
«окно k → k слотов» тогда не действует, проходимость определяет решатель.
Метрика `same_color_overlaps` считает такие совпадения. На кампании из
100 уровней у уровней с совпадениями больше ловушек (`trap_ratio` 0,115
против 0,091) и выше интересность (0,553 против 0,519), поэтому расстановщик
выбрал их в 70 случаях из 100.

Размещение машин сразу отбрасывает позиции, создающие круговую блокировку,
так что каждый собранный двор имеет полный порядок выезда.

Пул перебирает число машин, цветов и окно (раздел `pool` конфига).

## 2. Оценка — `level_solver.gd`, `level_evaluator.gd`

**Точный решатель** перебирает порядок выезда с запоминанием состояний и для
каждого числа слотов 1…5 даёт `solvable` (с решением), `unsolvable`
(доказано) или `timeout`. Отсюда `min_slots` — минимум слотов для прохождения.

**Модель игрока** (Монте-Карло, `player_runs` прогонов): с вероятностью
`player_skill` игрок выпускает машину, чей груз нужен конвейеру раньше всех,
иначе — любую доступную. При тупике тратит спасение (+1 слот), пока есть
`max_rescues`. Метрики:

| Поле | Смысл | Связь с экономикой |
| --- | --- | --- |
| `fail_rate` | доля прогонов без победы на базовых слотах | сложность, тир |
| `expected_rescues` | среднее число купленных спасений | отток монет |
| `post_rescue_fail` | проигрыш даже после 1 спасения | честность гейта |
| `speed_bonus_rate` | победа без заполнения буфера > 50 % | $B_{speed}$ |
| `clutch_rate` | победа, когда оставался 1 свободный слот | ачивка «На волоске» |

**Категории:**

- `regular` — проходится на 3 слотах; тир по `fail_rate`: easy ≤ 15 %,
  medium ≤ 30 %, hard ≤ 50 %, very_hard — выше.
  `soft_gate_eligible` — `fail_rate` в полосе `soft_gate_fail` (50–85 %).
- `slot_gate` — на 3 слотах **доказано** непроходим, на 4 проходим, и после
  одного спасения проигрывают не больше `slot_gate_max_post_rescue_fail`.
- `rejected` — нужно 5 слотов, решатель не уложился в лимит или гейт
  слишком жесток после спасения.

## 3. Расстановка — `level_sequencer.gd`

План каждого номера уровня:

1. `booster_tutorial_levels` (3) — обучение одному бустеру, см. раздел 5.
2. `onboarding` — первые уровни (по умолчанию 4).
3. Каждый `gate_every`-й (5-й) уровень — трудный. С `first_gate_level` (20)
   типы идут по `gate_pattern`: 20 — мягкий гейт, 25, 30, 35 — сложные,
   40 — мягкий гейт… Мягкий гейт — раз в 20 уровней.
4. Между ними — `rhythm`: easy → medium → hard → medium, то есть после
   трудного уровня всегда передышка.

**Ни один уровень не требует бустера по построению:** `evaluation.allow_slot_gates =
false` отбрасывает всё, что решатель не проходит на 3 слотах. Для уровней
1…`early_levels` (10) действует потолок `early_max_attempts` (3,5): новичок
(навык `novice_skill` = 0,35) проходит уровень без бустеров в среднем не
больше чем за 3,5 попытки.
Для каждого места выбирается неиспользованный уровень нужного типа с мерой
сложности ближе всего к цели: цель растёт внутри полосы `targets[тип]` от
уровня 1 до `ramp_levels`. Штрафы — за число машин вне растущего
диапазона `vehicles_start → vehicles_end` и за повтор параметров предыдущего
уровня. Если подходящего уровня нет, берётся соседний тип (`fallback` в отчёте).

В сводке `expected_rescues_per_10_levels` — ожидаемые спасения на каждый
десяток уровней: это вход для расчёта баланса монет.

## 4. Связь с экономикой

Оценщик дополнительно считает кривую проигрышей по навыку (`fail_by_skill`),
near-miss, ловушки (`trap_ratio`, `critical_share`) и интересность `interest`.
Расстановщик отбрасывает уровни с `interest` < `min_interest` и предпочитает
интересные. `levels.json` читается моделью экономики — см.
[ECONOMY-MODEL.md](ECONOMY-MODEL.md).

## 5. Обучение бустеру

Уровни `booster_tutorial_levels` (3) учат одному бустеру (`evaluation.booster_tutorial.booster`,
сейчас `slot`). Уровень проходится сам по себе, но новичок обычно упирается в
тупик: тогда всплывает подсказка и бустер выдаётся бесплатно.

- Отбор (`LevelSolver.onboarding_profile`): новичок (навык 0,35) упирается в тупик
  не реже `min_deadlock` (60 %), а после бесплатного бустера выигрывает не реже
  `min_post_win` (90 %). Не больше `max_vehicles` машин.
- Текущий уровень 3: 8 машин, 3 цвета, тупик у новичка в 66 % случаев, после слота
  выигрыш в 100 %.
- В `levels.json` у него есть поле `tutorial`. Около трети новичков проходят
  уровень без тупика и подсказку не видят; в игре стоит показать её при первом
  тупике на следующих уровнях.

Прежнее обучение перемешиванию (уровни, непроходимые без него) отключено:
`evaluation.shuffle_tutorial.enabled = false`. Код отбора (`tutorial_profile`,
`verified_shuffle`) оставлен. Умное перемешивание и его сила $K$ описаны в
[ECONOMY-MODEL.md](ECONOMY-MODEL.md), раздел 1а.
